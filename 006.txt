SCENARIO: You are using Claude Code to accelerate software development. Your team uses it for code generation, refactoring, debugging, and documentation. You need to integrate it into your development workflow using custom slash commands and CLAUDE.md configuration, and to know when to use plan mode rather than direct execution.
 
QUESTION: A senior developer on the team just finished a lengthy Claude Code session that thoroughly explored a legacy billing module, mapping its dependencies and identifying constraints for an upcoming refactoring; the session ID was captured. The team now wants to prototype two competing refactoring strategies, each building on that same completed analysis and each implemented in its own separate git worktree, and compare the results side by side without either attempt's reasoning or conversation history influencing the other. Which session management approach best supports this comparison?
Resume the original session by its session ID and evaluate both strategies sequentially, instructing Claude to disregard the first approach before starting the second.
Explanation
Resuming continues one session, so the first strategy's reasoning, tool calls, and edits remain in the conversation history when the second strategy begins. Instructions to disregard prior context are probabilistic and do not remove that history, so the second attempt is not an independent comparison.
Your answer is incorrect
Start two completely fresh sessions and have each one re-explore the legacy module independently before implementing its assigned strategy.
Explanation
Fresh sessions do achieve isolation, but they discard the completed analysis and force the expensive exploration to run twice. The two re-explorations may also surface different findings, so the strategies would no longer be compared against an identical baseline.
Correct answer
Fork the completed analysis session twice, giving each refactoring strategy its own independent branch that starts from a copy of the shared exploration history.
Explanation
Forking creates a new session that begins with a copy of the original conversation history while leaving the original unchanged. Two forks give each strategy the full analysis context as a starting point, and because each fork accumulates its own history independently, neither attempt's reasoning contaminates the other or the baseline.
Resume the original session for the first strategy, then use file checkpointing to restore the session transcript to the analysis baseline before attempting the second.
Explanation
File checkpointing reverts file changes, not conversation state; it does not rewind the session transcript. After the first attempt, the resumed session's history would still contain all of that strategy's reasoning, so the second attempt would not start from a clean analysis baseline.
Overall explanation
<p>The Claude Agent SDK and Claude Code persist a <b>session</b> as the accumulated conversation history: the prompt, every tool call, every tool result, and every response. Because this transcript is written to disk automatically, a completed run becomes a reusable asset. Three distinct operations act on it: <code>continue</code> picks up the most recent session in the current directory, <code>resume</code> reopens a specific session by ID and keeps appending to it, and <b>fork</b> creates a brand-new session seeded with a copy of the original history while leaving the original untouched.</p><p>Forking is the mechanism designed for exactly this situation: exploring <i>divergent</i> paths from a shared, expensive baseline. Each fork inherits the full exploration context, then diverges independently, so two refactoring strategies can be developed and compared from identical starting knowledge. Note that forking isolates only conversation state; keeping each prototype's file changes separate is a filesystem concern, which the team here addresses with separate git worktrees. Resuming a single session and switching strategies mid-conversation fails because history is append-only; asking the model to ignore earlier reasoning is a prompt-level request, not a state change. Starting fresh sessions achieves isolation at the cost of repeating the analysis, and the two re-explorations may not even reach the same findings, undermining the comparison. Finally, it is important to distinguish what session persistence covers: the SDK saves conversation history but does <i>not</i> snapshot the filesystem; <b>file checkpointing</b> exists to revert file edits and cannot rewind a transcript.</p><p>See <a href="https://code.claude.com/docs/en/agent-sdk/sessions">Agent SDK Sessions</a> for details on continuing, resuming, and forking sessions.</p>
