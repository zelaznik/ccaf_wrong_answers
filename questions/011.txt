SCENARIO: You are building a multi-agent research system using the Claude Agent SDK. A coordinator agent delegates to specialized subagents: one searches the web, one analyzes documents, one synthesizes findings, and one generates reports. The system researches topics and produces comprehensive, cited reports.
 
QUESTION: During testing, the synthesis subagent's output frequently references vague "industry reports" and invents citations instead of citing the specific sources the other agents actually found. The web search and document analysis subagents both completed successfully and returned detailed, source-attributed findings to the coordinator. The coordinator's logs show it invoked the synthesis subagent with the delegation prompt: "Synthesize the findings from the earlier research on this topic into key themes." What change most reliably fixes this handoff failure?
Correct answer
Modify the coordinator to embed the full search and analysis findings, with source URLs and document names, in the synthesis subagent's delegation prompt.
Explanation
Subagents start with fresh, isolated context and only receive what appears in their delegation prompt. Since the synthesis agent never saw the actual findings, it filled the gap with generic and fabricated references; passing the complete findings with source metadata directly in the prompt gives it the real material to synthesize and cite.
Your answer is incorrect
Update the synthesis subagent's system prompt with an instruction to review the coordinator's conversation history and cite only sources found there.
Explanation
A subagent does not inherit or have any access to the coordinator's conversation history; its context window starts fresh. An instruction to consult history it cannot see changes nothing, and the agent would still lack the actual findings.
Add the Task tool to the synthesis subagent's allowed tools so it can query the completed search subagent for the source-attributed findings it produced.
Explanation
Each subagent invocation creates a new instance with fresh context, so spawning a search-type subagent again would not retrieve what the earlier instance found; it would trigger a new, possibly different search. This also breaks the hub-and-spoke pattern where the coordinator routes information between workers.
Increase the synthesis subagent's turn limit so it has more iterations to gather the missing findings and sources before producing its final output.
Explanation
A higher turn limit only allows more tool-use cycles; it does not supply the missing search and analysis results, which exist only in the coordinator's context. The synthesis agent would still be working without the actual findings regardless of how many turns it is granted.
Overall explanation
<p>The defining property of subagents in the Claude Agent SDK is <b>context isolation</b>: each subagent runs in its own fresh conversation window with no access to the parent's history, prior tool results, or other subagents' outputs. The only channel from coordinator to subagent is the <i>delegation prompt</i> itself. When a coordinator writes a vague handoff like "synthesize the findings from the earlier research," the synthesis agent literally has no findings to work with, so the model does what language models do under missing information: it produces plausible-sounding but ungrounded content, including fabricated citations.</p><p>The correct fix follows the explicit context-passing rule: the coordinator must embed the complete findings, along with provenance metadata such as source URLs and document names, directly in the delegation prompt. Keeping content and source metadata structured through the handoff is what allows the final report to carry accurate citations. This is also why the hub-and-spoke pattern places the coordinator in charge of all information routing; workers cannot reach into each other's contexts, so the hub is the single point where results are collected and forwarded.</p><p>The distractors all fail for the same root reason: they attempt to give the synthesis agent access it architecturally cannot have. Prompt instructions to "review history" reference state that does not exist in the subagent's window; granting the Task tool spawns brand-new instances rather than reconnecting to a finished one's memory; and raising the turn limit only extends the tool-use loop without injecting the missing inputs. The mental model to internalize: if the coordinator did not put it in the prompt, it does not exist for that subagent.</p><p>See <a href="https://code.claude.com/docs/en/agent-sdk/agent-loop">Agent SDK Agent Loop</a> for how the SDK's loop and subagent delegation work.</p>
