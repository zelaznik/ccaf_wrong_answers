SCENARIO: You are using Claude Code to accelerate software development. Your team uses it for code generation, refactoring, debugging, and documentation. You need to integrate it into your development workflow using custom slash commands and CLAUDE.md configuration, and to know when to use plan mode rather than direct execution.
 
QUESTION: During a codebase-wide refactor to standardize error handling, Claude Code encountered several legacy patterns that your CLAUDE.md conventions do not address. It silently picked a different approach in each case, and developers later discovered inconsistent patterns mixed throughout the changed files. You want Claude Code to reliably stop and ask the developer when it hits a situation the team's conventions do not cover, while still proceeding autonomously on cases the conventions clearly address. Which approach best achieves this?
Let Claude apply its best judgment during the refactor and list any ambiguous decisions in a summary at the end for the developer to review afterward.
Explanation
Post-hoc flagging means the inconsistent changes have already been made across the codebase before anyone reviews them, recreating the original cleanup problem. It also still depends on the model recognizing its own ambiguous calls without any criteria defining what counts as ambiguous.
Your answer is incorrect
Require plan mode for every Claude Code task so the developer approves a proposed plan before any change is executed, regardless of the task's scope or complexity.
Explanation
Blanket plan mode adds approval overhead to simple, well-scoped tasks that do not need it, and approving an upfront plan does not guarantee the agent will surface convention gaps it encounters mid-execution. Plan mode is a valuable tool for complex work, but it does not substitute for explicit criteria defining when to ask the developer.
Instruct Claude to output a self-assessed confidence score for each change and ask the developer only when its confidence falls below a defined threshold.
Explanation
Self-reported confidence is an unreliable proxy for actual ambiguity; the model tends to be incorrectly confident on exactly the hard cases where it guessed. The failure described here is that Claude proceeded confidently on uncovered patterns, so a confidence threshold would not have triggered the desired pause.
Correct answer
Add criteria to CLAUDE.md directing Claude to pause and ask whenever it hits a pattern the conventions do not cover, with examples of when to ask versus proceed.
Explanation
Explicit escalation criteria paired with concrete examples give the model an operational definition of ambiguity: if the conventions are silent on a pattern, stop and ask. This targets the actual failure (guessing when guidance is absent) while still allowing autonomous work on cases the conventions clearly cover.
Overall explanation
<p>The core design question here is <b>ambiguity resolution</b>: how does an agent know when to act autonomously versus when to pause for human input? The reliable answer is <b>explicit escalation criteria with concrete examples</b>, not indirect signals. A rule like "if the team conventions do not cover the pattern you are looking at, stop and ask before changing it" gives the model a testable condition it can evaluate against CLAUDE.md, and two or three ask-versus-proceed examples anchor that rule far better than prose alone, because examples communicate the boundary unambiguously.</p><p>The mental model to carry is that a language model does not experience a distinct "I am unsure" state that maps cleanly to real case difficulty. That is why <i>self-reported confidence scores</i> fail as a routing mechanism: the model is often most confidently wrong precisely on the uncovered edge cases, so a threshold on its own confidence never fires when you need it. Similarly, end-of-run summaries of "ambiguous decisions" are post-hoc: by the time the developer reads them, inconsistent patterns are already spread across the codebase, and the summary still relies on the model detecting ambiguity without criteria defining it. Mandating plan mode for every task trades away the efficiency of direct execution on simple, well-understood changes, and an approved plan does not force the agent to surface convention gaps it only discovers while editing files mid-task.</p><p>Because <code>CLAUDE.md</code> is loaded as persistent project context on every session, it is the natural home for these escalation rules: they travel with the repository and apply consistently for every developer. This mirrors the general escalation principle for agents: escalate when there is a hole or gray area in the governing policy, and resolve autonomously only when the policy clearly covers the situation. See <a href="https://docs.anthropic.com/en/docs/claude-code/memory">Manage Claude's memory</a> and the <a href="https://docs.anthropic.com/en/docs/claude-code/overview">Claude Code Overview</a> for how CLAUDE.md context shapes agent behavior.</p>
