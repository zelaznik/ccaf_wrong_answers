SCENARIO: You are building a multi-agent research system using the Claude Agent SDK. A coordinator agent delegates to specialized subagents: one searches the web, one analyzes documents, one synthesizes findings, and one generates reports. The system researches topics and produces comprehensive, cited reports.
 
QUESTION: You are using Claude Code interactively to refine the report-generation subagent's prompt and formatting logic. Three separate times in the same session you have corrected Claude on the same issue: it keeps reintroducing numbered inline citations even though the reports require author-date citations. After each correction the next output looks right, but the problem resurfaces a few turns later, and the conversation now contains a long history of failed attempts and contradictory revisions. What is the most effective next step?
Restate the citation correction in the same session with progressively stronger and more emphatic wording each time the issue recurs.
Explanation
Repeating the same correction more forcefully does not address the root cause, which is a context now full of conflicting examples and failed revisions. The pattern of the fix working briefly and then regressing shows that additional in-session corrections are unlikely to stick.
Your answer is incorrect
Add the author-date citation rule to the project CLAUDE.md and continue in the current session, expecting the rule to take effect immediately.
Explanation
CLAUDE.md files load as context at the start of a session, so editing the file mid-session does not inject the rule into the current conversation. Capturing the rule in CLAUDE.md is worthwhile for future sessions, but continuing the polluted session and expecting immediate enforcement misunderstands both when memory loads and its advisory nature.
Run /compact to condense the conversation history into a summary, then continue issuing the same correction in the compacted session.
Explanation
Compacting summarizes the existing history rather than removing it, so the contradictory revisions and failed corrections are carried forward in summarized form. Summarization can also drop precise details, and it does nothing to establish the citation requirement as a clear upfront instruction.
Correct answer
Run /clear and start a fresh session with an initial prompt that explicitly states the author-date citation requirement up front.
Explanation
Anthropic recommends that when you have corrected Claude more than twice on the same issue, you should reset the context and start fresh with a better prompt that incorporates what you learned from the failed attempts. The accumulated history of failed attempts and contradictory revisions is itself polluting the context, so a clean session with the requirement stated up front is more effective than another in-session correction.
Overall explanation
<p>Iterative refinement with Claude Code works best when you recognize that the conversation itself is part of the system's state. Every failed attempt, contradictory revision, and correction stays in the context window and continues to influence subsequent outputs. When Claude fixes an issue and then regresses a few turns later, the usual culprit is not that Claude ignored you; it is that the context now contains competing signals, including the very examples of the wrong citation style you are trying to eliminate.</p><p>This is why Anthropic's guidance is direct: if you have corrected Claude more than twice on the same issue, run <code>/clear</code> and start over with a better prompt that incorporates what you learned. The failed session is not wasted effort; it told you exactly which requirement needs to be explicit from the first message (here, the author-date citation format). A fresh session that states that requirement up front gives Claude a clean, unambiguous context instead of a tug-of-war between old and new instructions.</p><p>The alternatives fall short for structural reasons. Escalating the emphasis of in-session corrections fights the accumulated context rather than removing it. <code>/compact</code> summarizes history instead of discarding it, so the conflicting material survives in condensed form and precise details can be lost in summarization. And while adding the rule to <i>CLAUDE.md</i> is a sensible way to persist the convention for future work, memory files load at session start and are advisory context rather than an enforcement mechanism, so editing one mid-session and continuing does not resolve the immediate problem.</p><p>See <a href="https://code.claude.com/docs/en/best-practices">Claude Code Best Practices</a> for guidance on course correction, context management, and when to reset versus continue a session.</p>
