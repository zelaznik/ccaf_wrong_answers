SCENARIO: You are building developer productivity tools using the Claude Agent SDK. The agent helps engineers explore unfamiliar codebases, understand legacy systems, generate boilerplate code, and automate repetitive tasks. It uses the built-in tools (Read, Write, Bash, Grep, Glob) and integrates with Model Context Protocol (MCP) servers.

QUESTION: Your team built an interactive Python CLI on the Agent SDK that lets an engineer ask a series of follow-up questions about a legacy codebase within a single long-running process. The current implementation issues an independent query() call for each question, and engineers report that the agent forgets earlier findings when they ask follow-ups. The tool runs on a shared development server where several engineers use the same repository checkout concurrently, each in their own process. What is the most reliable way to ensure each engineer's follow-up questions carry the full context of their own prior exchanges?
Pass continue_conversation=True on every query() call so each request resumes the most recent session in the working directory.
Explanation
The continue option resumes the most recent session found in the current directory, not the session belonging to a specific process. With several engineers running concurrently from the same repository checkout, an engineer's follow-up could resume a different engineer's session, mixing unrelated contexts.
Capture the session ID from the first result message and pass it with the fork option on every subsequent query() call.
Explanation
Forking creates a new session that starts from a copy of the original history while leaving the original unchanged. Forking the same original session on every follow-up means each question branches from the first exchange only, so later follow-ups never see the answers to earlier follow-ups.
Your answer is incorrect
Keep the independent query() calls but manually append a text summary of the prior responses to each new prompt.
Explanation
Manually re-injecting summaries loses the tool calls, file reads, and intermediate reasoning that made the earlier exploration valuable, and each summarization pass drops nuance. It also reimplements session management that the SDK already provides automatically, adding token cost and maintenance burden.
Correct answer
Use ClaudeSDKClient with one client per engineer's process so successive query() calls continue the same session.
Explanation
ClaudeSDKClient manages session IDs internally and automatically continues the same session across successive query() calls within the process. This gives each engineer's process its own isolated conversation, so follow-ups include all prior tool calls and findings without any risk of picking up another engineer's session.
Overall explanation
<p>In the Claude Agent SDK, a session is the accumulated conversation: the prompt, every tool call and result, and every response, written to disk so it can be continued later. The critical fact here is that a Python <code>query()</code> call creates a <b>fresh session by default</b>; nothing carries over between calls unless you explicitly continue, resume, or fork. When engineers see the agent "forget" earlier answers, the root cause is almost always independent <code>query()</code> calls that each start from a blank conversation.</p><p>For multi-turn state inside a single process, the documented tool is <code>ClaudeSDKClient</code>: it tracks the session ID internally and automatically continues the same session across successive <code>client.query()</code> calls. Because each engineer's process owns its own client, the design also cleanly isolates concurrent users on a shared machine, which is exactly where the <code>continue_conversation=True</code> shortcut breaks down. That option resumes the <i>most recent session in the working directory</i>, so on a shared checkout it can silently attach one engineer's follow-up to another engineer's conversation.</p><p>The other approaches misuse the session primitives. Forking is designed for branching: it copies the original history into a new session so you can explore divergent paths without mutating the source, which means forking the same ID repeatedly never accumulates follow-up context. Manually pasting summaries into each prompt discards tool results and reasoning, dilutes information with each summarization pass, and rebuilds by hand what the SDK's session persistence already guarantees.</p><p>See <a href="https://code.claude.com/docs/en/agent-sdk/sessions">Agent SDK Sessions</a> for the distinctions between continue, resume, and fork, and when to use <code>ClaudeSDKClient</code> versus one-shot <code>query()</code> calls.</p>
