SCENARIO: You are building a multi-agent research system using the Claude Agent SDK. A coordinator agent delegates to specialized subagents: one searches the web, one analyzes documents, one synthesizes findings, and one generates reports. The system researches topics and produces comprehensive, cited reports.
 
QUESTION: The document analysis subagent processes batches of 40 or more lengthy source documents within a single extended session. Logs show that for the first dozen documents, its extracted claims quote specific passages and cite the correct source names, but later in the session it begins attributing claims to the wrong documents and describing findings in generic terms rather than quoting actual content. Which change most effectively addresses this degradation?
Enable extended thinking for the subagent so it reasons more deliberately about which source each extracted claim came from before recording it.
Explanation
Extended thinking improves reasoning quality on complex problems, but it cannot recover information that has already degraded in a long context. The subagent's problem is that specific document content from earlier in the session is no longer reliably attended to, and no amount of additional reasoning restores information the model can no longer access accurately.
Your answer is incorrect
After each document, summarize the entire conversation so far and replace the accumulated history with that summary before processing the next document.
Explanation
Repeated summarization passes progressively dilute detail, and precise claim-source associations are exactly the kind of fine-grained information that gets lost first. After many rounds, the summaries would preserve general themes but lose the specific excerpts and source names the report requires, making misattribution worse rather than better.
Concatenate all source documents into a single initial request so the subagent sees the complete corpus at once instead of processing sequentially.
Explanation
Loading 40 or more lengthy documents into one prompt would consume a large share of the context window immediately and place most documents in the middle of a very long input, where the lost-in-the-middle effect reduces attention. This trades gradual degradation for immediate degradation and risks exceeding the context limit entirely.
Correct answer
Have the subagent append each document's key claims, excerpts, and source names to a scratchpad file, then reference it when processing later documents.
Explanation
A scratchpad file persists critical findings, including evidence excerpts and their source attributions, outside the conversation context, so claim-source associations survive even as earlier turns lose attention or are compacted away. Referencing the file during later extractions grounds the subagent in its recorded findings rather than degraded in-context memory, directly counteracting the misattribution and generic-answer symptoms.
Overall explanation
<p>The symptoms here (accurate, specific extraction early in a session that decays into misattribution and generic statements later) are the classic signature of <b>context degradation</b> in extended sessions. The context window is the primary resource an agent has to work with: every document read, every tool result, and every response accumulates there, and as it fills, the model attends less reliably to earlier material. Details in the middle of a long context are especially vulnerable, which is why claim-source associations, which depend on precise pairings of text and provenance, are among the first things to break down.</p><p>The effective mental model is that anything an agent must remember reliably across a long session should be <i>externalized</i>, not left implicit in conversation history. A <b>scratchpad file</b> does exactly this: the subagent writes each document's key claims, supporting excerpts, and source names to a persistent artifact as it works, then reads that artifact back when it needs earlier findings. The file is deterministic storage; unlike in-context memory, it does not decay, get compacted, or lose attention weight, and it also gives the synthesis stage a clean, structured record of provenance.</p><p>The alternatives all fail for structural reasons. Replacing history with rolling summaries falls into the <b>progressive summarization trap</b>: each pass loses nuance, and fine-grained source attributions are precisely the detail summaries discard. Extended thinking allocates more reasoning effort but cannot reconstruct information the context no longer represents faithfully. Front-loading the entire corpus into one giant request maximizes context pressure up front and buries most documents in the middle of the input, amplifying rather than mitigating the attention problem.</p><p>For more on why the context window should be treated as the scarce resource in long agent sessions, see <a href="https://code.claude.com/docs/en/best-practices">Claude Code Best Practices</a> and <a href="https://code.claude.com/docs/en/context-window">Context Windows</a>.</p>
