SCENARIO: You are building a customer support resolution agent using the Claude Agent SDK. The agent handles high-ambiguity requests like returns, billing disputes, and account issues. It has access to your backend systems through custom Model Context Protocol (MCP) tools (get_customer, lookup_order, process_refund, escalate_to_human). Your target is a first-contact resolution rate of 80% or higher, with reliable escalation to a human when a case falls outside what the agent should handle.
 
QUESTION: To improve consistency in how the agent handles return requests, your team pasted three complete example conversations (customer message, agent reasoning, tool call sequence, final response) as plain text into the system prompt, interleaved directly with the behavioral instructions. Return handling became more consistent, but the agent now occasionally references order numbers and customer names from the examples when talking to real customers, and it once called lookup_order with an order ID taken from an example. Which change would most effectively fix this problem while preserving the consistency benefits?
Your answer is incorrect
Replace concrete details in the examples with placeholder tokens such as [ORDER_ID] and [CUSTOMER_NAME] so no example data can leak into real conversations.
Explanation
Placeholders reduce the chance of a specific fake order ID leaking, but they degrade example quality because effective few-shot examples should closely mirror the real use case. It also fails to address the underlying boundary problem, so the agent can still confuse example reasoning, dates, or resolutions with the current case.
Remove the example conversations and expand the prose instructions to describe the desired resolution flow in greater detail.
Explanation
This discards the technique that produced the consistency improvement. Anthropic documents that providing examples of desired output is more effective than abstract instructions for driving consistent behavior, so replacing examples with longer prose would likely reintroduce the original inconsistency without guaranteeing the leakage stops.
Increase from three to ten example conversations so the correct pattern is reinforced strongly enough to override the confusion.
Explanation
Adding more undelimited example content does nothing to help the model distinguish demonstrations from live data; it increases the volume of fake order numbers and customer names available to leak into real conversations. Anthropic recommends roughly three to five relevant, diverse examples, and the failure here is structural, not a matter of insufficient examples.
Correct answer
Wrap each demonstration in <example> tags inside an enclosing <examples> block, structurally separated from the instructions and the live conversation.
Explanation
The root cause is that Claude cannot reliably distinguish demonstration content from instructions and live conversation data when everything is undelimited plain text. Anthropic specifically recommends wrapping individual examples in example tags and grouping them in an examples block so Claude can distinguish examples from instructions and live customer data, which preserves the consistency gains while substantially reducing the risk of example data leaking into real conversations.
Overall explanation
<p>The symptom in this case, an agent quoting order numbers from its own prompt examples and even passing an example order ID to <code>lookup_order</code>, is a classic sign of <b>missing delimitation</b>. When demonstrations, behavioral instructions, and live conversation data all sit in the same undifferentiated block of text, the model has no reliable signal for which content is illustrative and which is actionable. Anthropic's guidance is to wrap each demonstration in <code>&lt;example&gt;</code> tags and group them inside an <code>&lt;examples&gt;</code> block, and more generally to use XML tags such as <code>&lt;instructions&gt;</code> and <code>&lt;context&gt;</code> in complex prompts so different content types are much less likely to be misinterpreted.</p><p>The useful mental model is that few-shot examples steer <i>format, tone, and decision patterns</i>; they are training-like signal embedded in the prompt, not facts about the current customer. Structural tags give the model a clear signal to apply the pattern while disregarding the specific payload, which greatly reduces (though does not deterministically eliminate) the chance of example data bleeding into live interactions. This is why the fix is architectural rather than content-based: swapping in placeholders like [ORDER_ID] weakens the fidelity that makes examples effective (they should mirror the real use case closely) without fixing the boundary confusion, and adding more examples simply supplies more confusable material. Removing the examples in favor of longer prose is an anti-pattern here, since concrete examples are documented as more effective than abstract instructions for output consistency, and the team would trade a solvable leakage bug for the return of the original inconsistency.</p><p>For production agents, a well-structured prompt separates role, instructions, examples, and dynamic input into clearly tagged sections. See <a href="https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices">Claude prompting best practices</a> and <a href="https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/increase-consistency">Increase output consistency</a>.</p>
