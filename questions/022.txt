SCENARIO: You are building a multi-agent research system using the Claude Agent SDK. A coordinator agent delegates to specialized subagents: one searches the web, one analyzes documents, one synthesizes findings, and one generates reports. The system researches topics and produces comprehensive, cited reports.

QUESTION: During pilot runs, the synthesis subagent frequently encounters small factual questions (publication dates, correct spellings of researcher names, whether a cited statistic matches its source) and must pause and ask the coordinator to re-delegate each one to the web search subagent. This round-tripping adds significant latency and fills the coordinator's context with trivial delegation traffic, while deeper follow-up research genuinely does need the search subagent's full capabilities. How should you adjust the tool distribution to fix this?
Your answer is incorrect
Give the synthesis subagent the search subagent's complete web search and page-fetching toolset so it never needs to delegate any verification work.
Explanation
Cross-pollinating a full toolset into another agent's role blurs the role boundaries that make specialized subagents reliable, and adds tools the synthesis agent rarely needs, which degrades its tool selection. A scoped tool for the narrow, frequent need solves the latency problem without this cost.
Update the synthesis subagent's system prompt to mark unverified facts with an explicit caveat in the report instead of attempting any verification.
Explanation
This removes the delegation traffic by abandoning verification altogether, which directly undermines the system's stated purpose of producing comprehensive, cited reports. Deferring accuracy checks to readers is not a tool distribution strategy; it is a quality regression.
Have the coordinator pre-emptively spawn several parallel search subagents alongside every synthesis task to answer verification questions as they arise.
Explanation
Parallel subagent spawning is valuable when independent tasks are known up front, but verification needs emerge mid-synthesis and cannot be anticipated, so speculative searches would waste tokens without covering the actual questions. It also keeps the coordinator in the loop for every trivial lookup, which is the bottleneck being fixed.
Correct answer
Give the synthesis subagent a scoped fact-verification lookup tool, routing complex follow-up research through the coordinator to the search subagent.
Explanation
This is the scoped cross-role tool pattern: a limited, narrowly purposed tool handles the high-frequency, low-complexity need directly inside the synthesis agent, eliminating round trips for trivial confirmations. Complex research still flows through the coordinator, so each agent's role and tool set remain focused.
Overall explanation
<p>The core tension in tool distribution across a multi-agent system is between <b>scoped tool access</b> (each subagent gets only the tools its role needs, keeping tool selection reliable and roles clean) and the practical reality that some needs cross role boundaries. The design pattern for that tension is the <b>limited cross-role tool</b>: when one agent has a high-frequency but low-complexity need that formally belongs to another agent's role, give it a narrow, purpose-built tool for exactly that need, while continuing to route the complex cases through the coordinator to the specialist.</p><p>The mental model is a cost comparison. Every coordinator round trip costs latency (a full delegation cycle) and coordinator context (delegation prompts and returned results accumulate in its window). A scoped lookup tool costs one extra tool definition in the synthesis agent's set. For trivial confirmations like dates and spellings, the round trip is wildly disproportionate to the task; for genuine follow-up research, the search subagent's full capabilities and context isolation are worth the trip. Splitting the traffic along that line optimizes both.</p><p>Handing the synthesis agent the entire search toolset overshoots: it duplicates a specialist's capabilities inside an agent whose job is writing, expands its tool set with rarely used tools that dilute selection reliability, and invites the synthesis agent to drift into open-ended research inside its own context. Pre-spawning parallel search agents misapplies parallelization, which works for independent tasks known at delegation time, not for questions that only surface as synthesis proceeds. Flagging facts as unverified simply trades correctness for throughput, which is unacceptable in a system whose deliverable is cited, comprehensive reports.</p><p>For background on how client-executed tools are defined and invoked in the agent loop, see the <a href="https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview">Tool use overview</a> and <a href="https://docs.anthropic.com/en/docs/agents-and-tools/tool-use/implement-tool-use">How to implement tool use</a>.</p>
